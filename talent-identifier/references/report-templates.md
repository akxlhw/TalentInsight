# 报告结构与写作规范

阶段4 由 `scripts/render_report.py` 自动装配 Markdown/HTML/final JSONL；Agent 手写的部分是 Top20 小传中的**定性洞察**与**执行摘要关键发现**。本文档约定结构与措辞边界，手写内容与渲染器产物必须风格一致。

## 领域榜单报告（domain 模式，report.md 五段结构）

1. **执行摘要**：固定给出三项统计——候选总数、跨域关联成功数（linked_domains>1）、互联网补全动态条数；随后「关键发现」列出 Top3（`#rank 姓名 T-score（域列表）`，域用中文：学术/开源/实验室/竞赛/行业）；有动态时补一条动态总数。
2. **榜单总表**：表头 `| 排名 | 姓名 | T-score | 域 | 机构 |`，全体候选人按 rank 升序；t_score 为 null 显示 `N/A`；无任何域显示 `库外`。
3. **Top 榜单小传**：取榜单前 20 人，每人一节（结构见下）。
4. **跨域人才专题**（有跨域人才才出现）：每人一行「姓名：N 域（关联字段(置信度)；…）」。
5. **方法论附录**：固定口径说明——数据来源（Open API 五域，采集时间见 collected_at）、评分口径（候选集内归一化，仅本次可比；单域=域子分，跨域=0.7×最高+0.3×其余均值+广度加分 +5/域上限 +10）、关联口径（high=标识字段相同；medium=名字+机构；low=仅提示）、动态均带来源与证据分级；存在 gaps.txt 时追加「数据缺口域：…（当次采集失败，已跳过）」。

**小传结构**（渲染器生成骨架，`#### 定性洞察` 为手写）：`### #rank 姓名（T-score x）` → 域/机构行 → 各域关键指标（h-index/引用/stars/rating/org+title）→ 跨域关联证据 → 疑似同人警示（⚠️ 措辞：疑似、未合并）→ `#### 最新动态（互联网补全）`（按 date 降序，格式：`- [日期]（类型中文）标题 — 摘要（证据 level）[来源](url)`）→ `#### 定性洞察`。

## 个人报告（names 模式，report_<person_id>.md 每人一份）

- `# 人才深度洞察：<姓名>`（H1 只写人名）。
- `## 综合画像（T-score x）`：同小传结构但 H2 不再重复人名；域列表、机构、分域指标、关联证据、动态时间线、定性洞察。
- 末尾 `---` + `## 方法论`（同榜单附录口径，缺口域照列）。
- T-score 为 null（库外者无任何可评分域）时显示 N/A，画像几乎全靠互联网动态与洞察支撑，此时洞察可适当扩写。

## 定性洞察写作规范（亮点 / 风险 / 趋势）

- 固定三小节 `## 亮点` / `## 风险` / `## 趋势`，每节 2-4 句。
- **观点须引用动态或指标支撑**：「2026-03 论文 X 表明…」「h-index 42 高于本次榜单中位数」，不接受裸断言。
- **禁无依据推断**：不猜测薪酬、离职意向、健康、家庭；不推断未公开的动向。
- **禁臆造联系方式**：报告不得出现未经信源支撑的邮箱/电话/账号；PII 缺失时不写联系方式相关内容。
- low 置信关联只能表述为「疑似」，不得合并双方的动态或指标。
- 首行不写标题，直接 `## 亮点` 开头。

## 产物清单（check_pipeline 校验项）

| 模式 | Markdown | HTML | final JSONL |
|---|---|---|---|
| domain | `report.md`（单份榜单报告） | `report.html` | `final/talents_<run_id>.jsonl` |
| names | 每人一份 `report_<person_id>.md` | `report.html`（汇总图表） | 同上 |

final JSONL 每行字段：`person_id / name / name_en / org / in_library / linked_domains / t_score / rank / domain_scores / score_components / link_evidence / dynamics / insight_md / run_id / generated_at`（空值字段剔除）。

执行摘要渲染示例（结构参考，数字为占位）：

```markdown
- 本次识别候选 42 人，其中跨域关联成功 9 人；互联网补全动态 31 条。
- 关键发现：
  - #1 张三 T-score 88.4（学术、开源）
  - #2 李四 T-score 81.0（竞赛）
  - #3 Wang Wu T-score 76.5（行业）
```

## 渲染细节约定（写内容时须兼容）

- 表格单元格内的 `|` 必须转义为 `\|`；换行用 `<br>` 之外的纯文本表述（渲染器仅做管道转义与 HTML 转义，不解析内嵌 Markdown）。
- 动态排序：按 `date` 降序，无 date 的排最后——写动态时尽量给出 YYYY-MM。
- 孤儿动态（person_id 不在 profiles 中）**不渲染、不计数**，写了也白写。
- `t_score=null` 显示 `N/A`；空域显示「库外」；洞察文件首行若为 `#` 标题会被剥离。

## HTML 报告图表（report.html，自动生成）

| 图表 | 数据来源 | 说明 |
|---|---|---|
| T-score 直方图 | scores.jsonl 的 `t_score` | 0-100 十桶（0-10…90-100），100.0 计入 90-100 桶 |
| 域构成饼图 | `linked_domains` 展开 | 每人可贡献多域计数 |
| Top15 条形图 | `t_score` 非 null 前 15 人 | 姓名 × 分数 |
| 多域雷达图 | `domain_scores` ≥3 的前 5 人 | 各域子分 0-100 |

页头统计行（候选/跨域/动态数）与 Markdown 摘要同源计算，不会漂移；ECharts 优先用本地 `assets/echarts.min.js`，缺失时回退 CDN。
